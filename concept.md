# Концепция личного планировщика

Первоначальная концепция сохранена для контекста. Актуальные требования и сценарии находятся в [техническом задании](tz.md). При расхождениях применяется `tz.md`: расписание 06:00–23:00, без направлений, пересечений и задач без времени в плане; перенос по одной задаче через буфер.

## Назначение

Планировщик помогает распределять задачи по дням недели и времени, отмечать выполнение и находить просроченные задачи для переноса. Это личная веб-страница для использования на компьютере.

Будущая реализация состоит из трёх файлов: `index.html`, `style.css` и `script.js`. Данные хранятся в браузере через `localStorage`. Сервер, база данных и экспорт не предусмотрены.

## Подтверждённые требования

- основной экран показывает неделю;
- слева располагается отдельная колонка с буфером нераспределённых задач;
- неделя состоит из шести равных колонок: пять для понедельника–пятницы, шестая разделена горизонтально на субботу и воскресенье;
- предусмотрено расписание с 08:00 до 20:00;
- можно создавать задачи без конкретного времени;
- можно выбирать задачи из списка по названию и добавлять свои;
- задачу из библиотеки можно добавлять на разные дни как отдельные экземпляры;
- сквозных задач и отдельного списка шаблонов нет;
- выполнение отмечается галочкой, доступны два состояния: выполнена и не выполнена;
- отчёт показывает невыполненные задачи, срок которых уже прошёл;
- отчёты о просроченных задачах открываются в отдельном разделе;
- доступны просмотр прошлых недель и планирование будущих;
- правила срока и ручного переноса согласованы;
- интерфейс рассчитан на компьютер;
- оформление напоминает строгий бумажный планировщик, используется светлая тема;
- лист А4 служит визуальным ориентиром, печать не нужна.

## Компоновка экрана

В верхней части располагаются даты выбранной недели и управление навигацией. Слева находится буфер задач, справа расположены шесть колонок недели. Буфер не входит в эти шесть колонок.

В колонке рабочего дня сверху отображаются название дня и дата, затем задачи без времени, ниже находится расписание с 08:00 до 20:00. Шестая колонка содержит две отдельные области: субботу сверху и воскресенье снизу. Каждая область имеет свою дату, задачи без времени и доступ к расписанию.

Предложение для шестой колонки: разместить часовую сетку каждого выходного дня в области с внутренней прокруткой. Это позволяет сохранить разделение колонки пополам и доступ ко всему диапазону часов. Точную высоту областей нужно проверить при реализации.

Левая колонка содержит библиотеку задач, буфер нераспределённых экземпляров и кнопку добавления. Библиотека представляет собой обычный список названий задач, без отдельного редактора шаблонов. Галочка выполнения относится к конкретному экземпляру задачи в буфере или плане.

Отчёты о просроченных задачах открываются кнопкой в отдельном разделе. Они не занимают место в часовой сетке.

## Работа с задачами

Основной сценарий:

1. пользователь добавляет свою задачу или выбирает существующую из библиотеки;
2. назначает день и при необходимости время;
3. задача появляется в расписании или в области задач без времени;
4. после выполнения пользователь ставит галочку;
5. невыполненная задача с истёкшим сроком появляется в отчёте;
6. пользователь переносит её на другую дату или возвращает в буфер.

Предложение по управлению: поддержать перетаскивание из буфера на день и в часовую сетку, а также выбор даты и времени в карточке задачи. Второй способ нужен для точного назначения и удобного переноса.

Рабочая интерпретация библиотеки: выбор названия создаёт отдельный экземпляр задачи на выбранный день либо в буфере. Одно название можно использовать несколько раз. Выполнение экземпляра в понедельник не влияет на экземпляр во вторник. Перенос существующего экземпляра меняет его дату, а не создаёт копию. Отдельного списка шаблонов нет.

## Данные задачи

Для первой версии предлагается минимальная карточка:

- название, обязательное поле;
- ссылка на запись библиотеки, если задача добавлена из неё;
- дата планирования, необязательное поле для задачи в буфере;
- время начала, необязательное поле;
- время окончания, необязательное поле для отображения длительности;
- срок выполнения, по умолчанию совпадает с датой планирования;
- отметка выполнения;
- дата и время последней отметки выполнения, сохраняются автоматически.

У каждой задачи также есть внутренний идентификатор. Снятие галочки возвращает задачу в состояние «не выполнена» и очищает текущую отметку времени выполнения.

Описание, направления, приоритеты, чек-листы и комментарии не включаются в обязательный состав первой версии: ответ о выборе по названию не подтверждает необходимость этих полей.

## Задачи без времени

Сквозные задачи исключены. Одна запланированная задача относится к одному дню. Если она нужна каждый день, пользователь добавляет отдельные экземпляры из библиотеки.

Задачи без конкретного часа сохраняются согласно первоначальному ответу пользователя. Они относятся к одному дню, находятся над расписанием и могут быть выполнены в любой момент этого дня.

## Выполнение и просрочка

У задачи только два состояния: выполнена и не выполнена. Отдельные статусы «в работе», «отменена» и «выполнена частично» не нужны.

Согласованное правило просрочки:

- задача с датой срока и без времени становится просроченной после окончания этого дня;
- задача с явно заданным временем срока становится просроченной после наступления этого времени;
- время начала в расписании само по себе не считается сроком выполнения;
- задача без срока не попадает в отчёт;
- выполненная задача не попадает в отчёт.

Расчёт ведётся по локальному времени компьютера. Даты календарных дней сохраняются отдельно от времени, чтобы избежать смещения дня при преобразовании часовых поясов.

В отчёте видны название, текущая дата планирования и срок. Доступны действия: отметить выполненной, выбрать новую дату или вернуть в буфер.

При переносе обновляется дата планирования. Если срок совпадал с прежней датой планирования, он переносится вместе с ней. Отдельно заданный срок требует явного выбора нового срока. Возврат в буфер снимает дату и время планирования; срок сохраняется до явного изменения.

Автоматического переноса нет: решение о новой дате принимает пользователь. Массовый перенос и история переносов не входят в первую версию.

## Отдельные отчёты

Отдельный раздел просроченных задач подтверждён пользователем. Предложение по составу раздела:

- отчёт за выбранную неделю показывает невыполненные задачи, срок которых приходится на эту неделю и уже прошёл;
- общий отчёт показывает все невыполненные задачи с истёкшим сроком, включая прошлые недели и задачи в буфере с сохранённым сроком.

Два отчёта используют одинаковые правила просрочки. Для каждого показываются список задач и их количество. Разделение на два отчёта является предложением по реализации, поскольку пользователь не уточнил их состав.

## Навигация по неделям

Навигация согласована: при открытии показывается текущая неделя, доступны кнопки перехода на предыдущую, следующую и текущую неделю. Неделя начинается в понедельник.

Задачи прошлых недель сохраняются, будущие недели доступны для планирования. Автоматическое повторение не входит в первую версию. Задачи на разные дни пользователь добавляет из библиотеки вручную.

## Визуальный стиль

Светлый фон, тёмный текст, тонкие линии и сдержанная типографика. Расписание визуально напоминает бумажную таблицу. Выполненные задачи остаются читаемыми, но выделяются галочкой и менее контрастным оформлением. Просроченные задачи получают небольшой цветовой акцент и текстовую отметку.

Основное пространство отдано задачам. Декоративные элементы, тяжёлые эффекты и анимация не нужны. При недостаточной ширине окна допускается горизонтальная прокрутка недельного плана вместо сжатия текста до нечитаемого размера.

## Хранение, скорость и безопасность

Все изменения автоматически сохраняются в `localStorage`. При повторном открытии страницы задачи и отметки восстанавливаются. Планируется версионировать формат данных для последующих изменений.

Данные привязаны к браузеру и адресу страницы. Очистка данных браузера может удалить планировщик. Между браузерами и устройствами синхронизации нет. Для предсказуемого хранения предпочтительно открывать страницу по постоянному адресу; поведение `localStorage` при открытии через `file:` зависит от браузера. Технический источник: [документация MDN о localStorage](https://developer.mozilla.org/en-US/docs/Web/API/Window/localStorage).

Предлагается использовать обычный JavaScript без фреймворков, внешних шрифтов, CDN и сетевых запросов. Это сокращает зависимости и позволяет подготовить страницу для размещения на домене `.ru` без внешних сервисов.

Ввод пользователя отображается как текст, без исполнения HTML. Загруженные данные проверяются перед использованием. Ошибки чтения, повреждённые данные и невозможность сохранения должны отображаться понятным сообщением; приложение не должно молча перезаписывать повреждённое хранилище.

Цвет текста кнопок задаётся явно для обычного состояния, наведения, фокуса, нажатия и отключения. Проверка реализации включает читаемость элементов, работу галочек, сохранение после перезагрузки, расчёт просрочки и отсутствие исполнения HTML из названий задач.

## Границы первой версии

Первая версия включает недельный экран, навигацию по неделям, библиотеку задач, буфер, расписание, задачи без времени, добавление и редактирование задач, галочку выполнения, локальное сохранение, отдельный раздел отчётов о просрочке и ручной перенос.

Не предусмотрены печать, экспорт, сервер, база данных, синхронизация, тёмная тема, сквозные задачи и отдельный список шаблонов. Автоматическое повторение, массовый перенос и история переносов не входят в первую версию.

## Рабочие решения для реализации

- библиотека является списком названий для добавления независимых экземпляров задач;
- задачи без часа сохраняются, сквозные задачи исключены;
- раздел просрочки содержит отчёт за выбранную неделю и общий отчёт;
- часовые сетки субботы и воскресенья имеют внутреннюю прокрутку при нехватке места.

Эти решения конкретизируют интерфейс. Интерпретация библиотеки и состав отчётов отмечены как предложения, остальные согласованные требования зафиксированы выше. Код и файлы страницы на этом этапе не создаются.
