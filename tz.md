# Техническое задание на личный недельный планировщик

## 1. Назначение и приоритет требований

Продукт представляет собой личный недельный планировщик для одного пользователя. Пользователь собирает задачи в библиотеке и буфере, распределяет их по времени, отмечает выполнение и вручную переносит невыполненные задачи.

Реализация состоит ровно из трёх файлов: `index.html`, `style.css`, `script.js`. Пользователь открывает `index.html` двойным нажатием. Сборка, установка зависимостей, сервер и доступ к интернету для работы не нужны. Все данные хранятся в `localStorage`.

Это ТЗ заменяет прежние решения в `concept.md` при расхождениях. В частности, диапазон времени теперь составляет 06:00–23:00, направления и задачи без времени исключены, пересечения запрещены, отметка выполнения доступна в плане, перенос выполняется по одной задаче через буфер.

Требования пользователя обязательны. Поведение, которое пользователь отдельно не определил, закреплено ниже как решение ТЗ. Разработчик реализует эти решения без добавления функций по собственной инициативе. Они не выдаются за дословные ответы пользователя.

## 2. Пользователь и границы продукта

Единственный участник системы: владелец планировщика. Он может управлять всеми своими задачами, библиотекой, расписанием и отчётами. Других ролей нет.

Регистрация, авторизация, аккаунты, совместный доступ, облачная синхронизация, уведомления через внешние сервисы, экспорт, импорт, печать, тёмная тема, мобильный интерфейс, автоматические повторения, массовый перенос, история переносов и отдельный редактор шаблонов не входят в продукт.

Приоритеты, направления, цветовые категории, чек-листы и комментарии о результате также исключены. Поле «описание» сохраняется.

Отсутствие авторизации означает, что любой человек с доступом к тому же профилю браузера и странице может открыть данные. Продукт не реализует защиту от других пользователей компьютера.

## 3. Решения ТЗ по неуточнённым деталям

- разовые задачи можно создавать без добавления в библиотеку;
- библиотека поддерживает поиск, создание, редактирование и удаление;
- задача дублируется по одной, копия попадает в буфер;
- одновременное добавление на несколько дней отсутствует;
- выполненные задачи остаются в плане, есть переключатель «скрыть выполненные»;
- дата и время выполнения отображаются в карточке;
- удаление выполняется после подтверждения, без таймера и временной блокировки интерфейса;
- отчёты включают просрочку за выбранную неделю, общую просрочку и итоги выбранной недели;
- сегодняшний день и текущее время выделяются;
- старт пустой, примеры загружаются отдельной кнопкой по желанию пользователя;
- в справке доступен явно подтверждаемый сброс только данных планировщика;
- основной сценарий рассчитан на одну вкладку, поведение дополнительных вкладок определено в разделе хранения.

## 4. Состав интерфейса

### 4.1. верхняя панель

Показывает название продукта, диапазон дат выбранной недели и элементы управления:

- «предыдущая неделя»;
- «текущая неделя»;
- «следующая неделя»;
- «добавить задачу»;
- «отчёты»;
- «справка», панель с правилами хранения и действием сброса из раздела 12.1;
- переключатель «скрыть выполненные».

Неделя начинается в понедельник и заканчивается в воскресенье. Переходы сдвигают выбранную неделю на семь календарных дней. На каждом запуске открывается текущая неделя по локальной дате компьютера. Прошлые и будущие недели доступны без ограничений внутри допустимого диапазона дат.

### 4.2. левая колонка

Фиксированная ширина 260 пикселей. Содержит две вкладки: «библиотека» и «буфер». Вкладка по умолчанию: «буфер». В заголовках показывается количество записей.

Библиотека содержит названия, описания и длительность задач, пригодных для многократного использования. Отдельного списка шаблонов нет.

Буфер содержит две группы:

- «нераспределённые», конкретные задачи без назначенного временного интервала;
- «просроченные», невыполненные задачи с истёкшим сроком, доступные для повторного планирования.

Просроченная задача может оставаться в прежнем дне расписания. Её появление в группе «просроченные» является дополнительным отображением той же записи, а не созданием копии. Нераспределённая просроченная задача показывается только в группе «просроченные».

Обе вкладки имеют поиск по названию. Поиск нечувствителен к регистру, пробелы по краям запроса игнорируются. Пустой запрос показывает все записи. Поиск не изменяет расписание и отчёты.

### 4.3. недельный план

Рабочая область имеет две соседние части: левая колонка шириной 260 пикселей с `flex-shrink: 0` и контейнер плана с `min-width: 0`, занимающий оставшуюся ширину. Только контейнер плана имеет горизонтальную прокрутку `overflow-x: auto`; внутри расположена сетка минимальной шириной 900 пикселей. Горизонтальная прокрутка страницы и общего контейнера с левой колонкой запрещена. Левая колонка остаётся на месте при прокрутке плана. Справа от левой колонки находится таблица из шести равных по ширине колонок. Понедельник–пятница занимают по одной колонке. Шестая разделена на две равные по высоте области: субботу сверху и воскресенье снизу.

У каждого дня есть заголовок с названием и датой, расписание и пустые интервалы для добавления задач. Рабочие дни имеют общую вертикальную прокрутку, чтобы их часы оставались выровненными. У субботы и воскресенья отдельная вертикальная прокрутка. Заголовки остаются видимыми при прокрутке.

Сетка содержит 34 интервала по 30 минут: первый 06:00–06:30, последний 22:30–23:00. Метка 23:00 обозначает нижнюю границу, создать задачу с началом в 23:00 нельзя. Высота интервала 30 пикселей, полная высота сетки дня 1020 пикселей. Часы подписываются в каждой колонке; получасовые границы обозначаются более светлыми линиями.

Карточка занимает высоту, соответствующую её длительности, с `box-sizing: border-box`. Для задач от 60 минут показывает галочку, название и временной диапазон.

Для 30-минутной задачи обязателен компактный однострочный режим: высота 30 пикселей, вертикальные отступы не более 3 пикселей, галочка 16×16 пикселей, текст 12 пикселей с высотой строки 18 пикселей. Галочка не сжимается, название имеет `min-width: 0`, `white-space: nowrap`, `text-overflow: ellipsis` и `overflow: hidden`. Отдельная строка времени отсутствует. Полное название и диапазон времени показываются в `title`, доступном имени элемента открытия и карточке редактирования. Не скрывать галочку или индикатор клавиатурного фокуса обрезкой контейнера.

У сегодняшнего дня выделяется заголовок. Линия текущего времени показывается только в сегодняшнем дне между 06:00 и 23:00, обновляется раз в минуту и не перехватывает нажатия. Отображение выполненных задач можно скрыть, но их временные интервалы остаются занятыми. В скрытом интервале показывается нейтральная отметка «выполненная задача», чтобы слот не выглядел свободным.

### 4.4. окно задачи

Создание и редактирование используют модальное окно с явно подписанными полями. Режимы: «в буфер» и «в расписание».

В режиме буфера дата планирования и часы не вводятся. Длительность задаётся для будущего размещения. В режиме расписания обязательны дата, начало и окончание. Описание и отдельный срок необязательны.

Кнопки: «сохранить» и «отмена». В режиме редактирования дополнительно доступны «дублировать» и «удалить». Существующая запланированная задача имеет действие «вернуть в буфер». Галочка выполнения в модальном окне отсутствует: выполнение меняется в плане.

Нажатие Escape и закрытие окна не сохраняют изменения. При наличии несохранённых изменений сначала показывается внутренний вопрос «закрыть без сохранения?» с кнопками «продолжить редактирование» и «закрыть». Enter в многострочном описании добавляет новую строку. Сохранение доступно явной кнопкой.

### 4.5. раздел отчётов

Открывается отдельной панелью поверх основного интерфейса. Имеет три вкладки: «просроченные за неделю», «все просроченные», «итоги недели». Панель показывает выбранную неделю там, где отчёт зависит от неё.

Отчёты вычисляются из текущих задач и не сохраняются как отдельные копии. Предусмотрены пустые состояния с понятным текстом.

## 5. Данные и ограничения

### 5.1. запись библиотеки

| поле | формат | правило |
| --- | --- | --- |
| `id` | уникальная строка | создаётся приложением |
| `title` | строка | обязательно, 1–120 символов после удаления крайних пробелов |
| `description` | строка | необязательно, не более 4000 символов |
| `durationMinutes` | целое число | кратно 30, от 30 до 1020, по умолчанию 30 |
| `createdAt`, `updatedAt` | строка ISO с часовым поясом | служебные отметки времени |

Названия могут совпадать. Новая запись создаётся только явным действием. Список сортируется по названию через русскую локаль, одинаковые названия по времени создания.

Редактирование записи меняет только библиотеку и будущие добавления. Уже созданные экземпляры сохраняют название, описание и длительность. Удаление записи не удаляет экземпляры; их `libraryId` становится `null`.

### 5.2. конкретная задача

| поле | формат | правило |
| --- | --- | --- |
| `id` | уникальная строка | не меняется при переносе |
| `libraryId` | строка или `null` | ссылка на источник, не источник текущих полей |
| `title` | строка | обязательно, 1–120 символов |
| `description` | строка | необязательно, до 4000 символов |
| `plannedDate` | `YYYY-MM-DD` или `null` | день размещения |
| `startMinutes` | целое число или `null` | минуты от полуночи, 360–1350, кратно 30 |
| `endMinutes` | целое число или `null` | минуты от полуночи, 390–1380, кратно 30 |
| `durationMinutes` | целое число | кратно 30, 30–1020 |
| `deadlineMode` | `auto` или `manual` | источник срока |
| `deadlineDate` | `YYYY-MM-DD` или `null` | дата окончания срока, без часа |
| `completed` | boolean | по умолчанию `false` |
| `completedAt` | ISO-строка или `null` | время последней действующей отметки выполнения |
| `createdAt`, `updatedAt` | ISO-строки | служебные отметки времени |

Для запланированной задачи `plannedDate`, `startMinutes`, `endMinutes` заполнены одновременно; `endMinutes > startMinutes`; `durationMinutes = endMinutes - startMinutes`.

Для задачи в буфере все три поля размещения равны `null`, длительность сохраняется. Это не задача без времени на день: она вообще не размещена в календаре.

Один экземпляр принадлежит одному дню. Переход через полночь запрещён. Допустимые календарные даты: 2000-01-01–2099-12-31. На границах диапазона недоступная навигация отключается.

### 5.3. ограничения ввода

Для названия установить `maxlength="120"`, для описания `maxlength="4000"`. Под обоими полями постоянно показывать счётчик текущей длины и лимита. Единица подсчёта совпадает с HTML `maxlength` и JavaScript `String.length` (кодовые единицы UTF-16); составные символы могут занимать несколько единиц. Валидация сохранения и чтения данных использует тот же подсчёт.

Название из одних пробелов не принимается. Ошибка отображается под полем, поле получает `aria-invalid`, фокус переходит к первому ошибочному полю. Если ввод или вставка превышают лимит, лишняя часть не принимается, появляется сообщение «достигнут лимит поля» через `aria-live`. Вставку обработать явно, сохранив допустимую часть и выделение; не допускать необъявленного обрезания. Некорректные данные из хранилища не обрезать, применять правила раздела 15.

При создании ID использовать `crypto.randomUUID`, если доступен, иначе локальный генератор с проверкой уникальности среди существующих записей. Не делать доступность `crypto.randomUUID` условием запуска через `file:`.

## 6. Библиотека и создание экземпляров

Создать запись библиотеки можно кнопкой внутри её вкладки. Поля: название, описание, длительность. При создании разовой задачи есть необязательный переключатель «добавить в библиотеку», выключенный по умолчанию. При его включении библиотечная запись и экземпляр сохраняются одной операцией.

Добавление из библиотеки копирует её поля в новый экземпляр. По кнопке «в буфер» экземпляр создаётся без размещения и срока. При перетаскивании в свободное время создаётся запланированный экземпляр с автоматическим сроком на выбранный день.

Перетаскивание записи библиотеки всегда создаёт новый экземпляр, не убирает запись из библиотеки и не изменяет уже существующие экземпляры. Отдельные задачи из одного источника имеют независимые сроки и галочки.

Дублирование конкретной задачи создаёт новую задачу в буфере, копирует название, описание, длительность и ссылку на библиотеку. Размещение, срок и выполнение сбрасываются. Оригинал остаётся без изменений.

## 7. Планирование, интервалы и запрет пересечений

Создание в расписании доступно через верхнюю кнопку, нажатие на свободный интервал и перетаскивание из библиотеки или буфера.

Нажатие на интервал открывает окно с выбранными датой и началом; окончание по умолчанию на 30 минут позже. Верхняя кнопка открывает режим буфера. В режиме расписания пользователь выбирает свободный интервал самостоятельно.

Два интервала одного дня конфликтуют, если начало первого раньше окончания второго и окончание первого позже начала второго. Интервалы трактуются как полуоткрытые: окончание одной задачи может совпадать с началом другой. Например, 09:00–09:30 и 09:30–10:00 разрешены, 09:00–10:00 и 09:30–10:30 запрещены.

Проверка учитывает все запланированные задачи, включая выполненные и скрытые. При редактировании текущая задача исключается из сравнения с самой собой. Суббота и воскресенье считаются разными днями.

При конфликте операция не сохраняется. Сообщение: «это время занято задачей «…». выберите другой интервал». Прежние данные остаются нетронутыми. Автоматический сдвиг, сокращение задачи и подбор другого времени отсутствуют.

Длительность можно изменить через поля начала и окончания, только с шагом 30 минут. Растягивание карточки мышью не входит в первую версию.

При перетаскивании вычислять слот по координатам внутри нужного дня с учётом его прокрутки. Подсвечивать допустимый слот и предполагаемый интервал. При выходе за 23:00 или конфликте показывать недопустимое размещение и не сохранять его. Бросок вне сетки отменяет действие.

Кнопка «запланировать» у задачи буфера предоставляет альтернативу перетаскиванию и открывает форму даты и часов. Длительность подставляется из задачи.

Изменить название, описание, длительность и отдельный срок можно в карточке. Для изменения дня или начала существующую задачу сначала возвращают в буфер. Прямое перетаскивание между днями и прямое изменение размещения в форме не предусмотрены. После возврата пользователь выбирает новый день и время. Изменение окончания на месте разрешено с проверкой пересечений.

## 8. Срок и отчётность после окончания дня

Срок имеет только календарную дату. Час срока отсутствует. Плановая задача с окончанием в 10:00 не становится просроченной в 10:01.

Автоматический срок при первом размещении совпадает с днём планирования. Пользователь может включить отдельный срок и указать другую дату. Задача в буфере может иметь отдельный срок без размещения.

Задача просрочена, если одновременно:

- `completed` равно `false`;
- срок задан;
- `deadlineDate` меньше сегодняшней локальной календарной даты.

Задача со сроком сегодня не попадает в просрочку до следующего дня. В 00:00 следующего локального дня она появляется в просрочке, если не выполнена. Отчёт можно открыть в любой момент, но задачи включаются в него только после окончания дня срока.

Просрочка обновляется при запуске, после изменений, раз в минуту и при возвращении фокуса во вкладку. Открытая через полночь страница обновляет дату, выделение сегодняшнего дня и отчёты. Выбранная пользователем неделя сама не переключается.

Календарные даты сравниваются как проверенные строки `YYYY-MM-DD`. Не получать сегодняшнюю дату через UTC-часть `toISOString`, не разбирать дату дня через `new Date('YYYY-MM-DD')` для локальных вычислений. Использовать локальные компоненты даты, недельные переходы считать календарными днями, а не фиксированными миллисекундами.

## 9. Выполнение

Галочка доступна только на карточке задачи в недельном плане. Установить её можно для задачи любой отображаемой недели. Отметка сохраняет `completed = true` и текущее время компьютера в `completedAt`. Задача исчезает из просрочки и группы невыполненных задач буфера, но сохраняется в расписании.

Снятие галочки устанавливает `completed = false`, `completedAt = null`. При истёкшем сроке задача сразу возвращается в просрочку. Галочка не меняет название, интервал и срок.

В карточке редактирования выполненной задачи показывается время выполнения в локальном формате. Фактическая длительность работы не отслеживается.

В отчёте кнопка «открыть в плане» закрывает панель отчёта, переключает неделю, дожидается обновления сетки и прокручивает горизонтальный контейнер к нужной колонке. Затем прокручивает рабочую сетку либо отдельную область субботы или воскресенья к карточке. Карточка короче видимой области должна быть видна целиком; для более высокой карточки показать её начало. Установить фокус на элемент открытия карточки и выделить её на 2 секунды. Переход не должен прокручивать соседний выходной день. Для скрытой выполненной задачи переход временно отключает скрытие. Непосредственной галочки в отчёте и буфере нет.

## 10. Буфер и ручной перенос

Просроченная задача отображается в буфере автоматически как доступный для планирования экземпляр. Это не автоматический перенос: прежняя дата и время остаются до действия пользователя.

Пользователь переносит по одной задаче из буфера на выбранную дату и свободное время. При успешном размещении сохраняются ID, название, описание и длительность; прежний интервал освобождается. Проверка нового интервала и сохранение выполняются как одна операция. Ошибка не должна сначала удалить старое размещение.

Для срока действуют правила:

- режим `auto`: срок меняется на новый день планирования;
- режим `manual`, перетаскивание: срок и режим сохраняются без модального окна; дата размещения не подменяет явно заданный срок;
- режим `manual`, кнопка «запланировать»: форма показывает прежний срок и требует явного выбора «сохранить срок» или «задать новый срок»;
- отдельный срок может быть раньше даты размещения. При перетаскивании после успешного сохранения показывать сообщение «задача перенесена, срок сохранён: дд.мм.гггг», а при истёкшем сроке дополнительно «задача остаётся просроченной». В форме предупреждать до сохранения и разрешать подтверждение пользователем.

Сведения о сроке показывать в карточке буфера до перетаскивания. Не менять `manual` на `auto` скрыто. Если пользователь хочет изменить срок, он использует форму планирования или редактирования. При конфликте интервалов никакие поля, включая срок, не меняются.

При возврате в буфер освобождается временной интервал, сохраняются длительность и срок. Автоматический срок временно сохраняется как последняя дата; при новом размещении обновляется на новый день. Пока он истёк, задача остаётся в просрочке.

Выполненную задачу нельзя вернуть в буфер или перенести. Сначала пользователь снимает галочку в плане. Можно дублировать выполненную задачу в буфер как новый невыполненный экземпляр.

Ни автоматического распределения на новую неделю, ни массового переноса нет. Из отчёта кнопка «в буфер» открывает левую вкладку и выделяет тот же экземпляр в группе просроченных. Прежнее размещение этим переходом не изменяется.

Группа нераспределённых сортируется по времени создания, старые первыми. Группа просроченных сортируется по сроку, затем по названию и ID. Ручная сортировка не предусмотрена.

## 11. Отчёты

### 11.1. просроченные за неделю

Включает текущие невыполненные задачи с истёкшим сроком, если дата срока попадает в выбранную неделю. Критерий недели определяется сроком, а не датой размещения. Включает задачи буфера с отдельным сроком.

Поля строки: название, дата срока, дата и время размещения либо «в буфере», количество календарных дней просрочки. Действия: «открыть в плане», если задача размещена, «в буфер» и «открыть карточку». Показывается общее количество строк.

### 11.2. все просроченные

Тот же состав полей и действий, без ограничения выбранной неделей. Сортировка обоих отчётов: срок по возрастанию, название, ID. Если просроченных задач нет, текст «просроченных задач нет».

### 11.3. итоги недели

Считаются по текущей дате размещения задач в выбранной неделе:

- запланировано, все размещённые задачи недели;
- выполнено, размещённые задачи с галочкой;
- не выполнено, размещённые задачи без галочки;
- из них просрочено, невыполненные размещённые задачи с истёкшим сроком;
- процент выполнения, выполнено / запланировано × 100, округление до целого; для пустой недели показывать 0%.

Ниже выводятся невыполненные задачи этой недели, включая те, срок которых ещё не прошёл. Непросроченные строки явно отличаются от просроченных. Порядок: дата размещения, начало, ID.

После переноса задача учитывается в новой неделе. Исторические показатели старой недели не сохраняются. Возврат в буфер исключает задачу из итогов недели, но не обязательно из отчёта просрочки. Все отчёты описывают текущее состояние, а не историю действий.

## 12. Удаление

Удаление экземпляра убирает его из расписания, буфера и отчётов, но не из библиотеки. Удаление библиотечной записи не удаляет экземпляры.

Перед удалением показать внутренний диалог с названием записи и кнопками «отмена» и «удалить». По умолчанию фокус находится на «отмена». Для записи библиотеки пояснить, что уже созданные задачи останутся. Escape отменяет действие. До подтверждения данные не меняются.

После подтверждения удалить запись и сохранить кандидат состояния по правилам раздела 15. При ошибке записи данные остаются нетронутыми. Таймер, отмена после удаления и блокировка интерфейса на несколько секунд отсутствуют.

### 12.1. сброс данных планировщика

В панели «справка» есть отдельное действие «сбросить данные планировщика». Оно доступно также на экране ошибки повреждённых данных или переполнения хранилища. Не использовать скрытые сочетания клавиш, URL-параметры или автоматический сброс.

Диалог перечисляет последствия: удаление библиотеки, всех задач и настроек без возможности восстановления. Пользователь должен ввести слово «удалить» и нажать «удалить все данные». До ввода точного слова кнопка отключена. Escape и «отмена» сохраняют данные.

После подтверждения удалить только ключ `personal-week-planner:v1` через `removeItem`. Не применять `localStorage.clear()` и не трогать другие ключи. Это единственное разрешённое явное удаление повреждённого состояния. Проверить отсутствие ключа; при успехе закрыть все формы и отчёты, очистить состояние в памяти и открыть пустой план текущей недели с настройками по умолчанию и кнопкой примеров. Не записывать пустой JSON сразу после сброса. Если удаление невозможно, показать ошибку, не сообщать об успехе.

Сброс не устраняет запрет браузера на сохранение. После него повторить проверку доступности хранилища; при неудаче ограничения раздела 15 сохраняются.

## 13. Первый запуск и демонстрационные данные

Если сохранённых данных нет, открываются текущая неделя, пустой план и пустые списки. Подсказки объясняют создание задачи, библиотеку и перетаскивание. В пустом состоянии есть кнопка «загрузить примеры». Автоматически примеры не добавляются.

Кнопка доступна только если библиотека и список экземпляров пусты. Нажатие создаёт три записи библиотеки с длительностью 30, 60 и 30 минут и четыре экземпляра: два непересекающихся в сегодняшнем плане (один выполненный, один невыполненный), один в буфере без срока и один в буфере со сроком вчера. Примеры должны демонстрировать независимые экземпляры библиотеки и разовую задачу без библиотечного источника. Автоматические сроки совпадают с датой размещения, время выполнения равно времени загрузки.

Названия, описания, связи и конкретные интервалы задаются единым массивом констант `DEMO_DATA` в `script.js`. Даты вычисляются относительно дня загрузки. Тексты могут быть выбраны разработчиком на русском языке; они не являются частью критериев приёмки. Массив проходит обычную валидацию до единой записи в хранилище.

Примеры используют обычные записи и поддерживают все операции. Загрузка сохраняется атомарно и не повторяется поверх существующих данных. Если сегодняшний или вчерашний день вне допустимого диапазона, кнопка недоступна с объяснением.

## 15. Хранение и восстановление

Ключ `localStorage`: `personal-week-planner:v1`. Значение представляет собой JSON-объект с `schemaVersion: 1`, `revision` (целое число), `library` (массив), `tasks` (массив), `preferences` (объект с `hideCompleted`) и `savedAt` (ISO-строка).

Представления отчётов, просрочка и содержимое групп буфера вычисляются из этих данных. Выбранная неделя, поисковый запрос, открытые окна и прокрутка не сохраняются.

При сохранении сначала создать и проверить кандидат состояния, сериализовать и записать его в `localStorage`, затем обновить основное состояние и интерфейс. Если запись не удалась, прежние данные и размещение сохраняются, форма остаётся открытой. Галочка также откатывается. Нельзя показывать успех при неудачной записи.

При запуске проверить доступность хранилища пробной записью и удалением отдельного временного ключа. Если хранилище недоступно, показать сообщение «не удалось сохранить данные в браузере: хранилище недоступно или заполнено» и заблокировать обычное создание и изменение задач. Явный сброс остаётся доступен по разделу 12.1; успешность `removeItem` проверяется отдельно. Просмотр корректных доступных данных разрешён. Нельзя молча переходить на хранение только в памяти.

При чтении проверять JSON, версию, типы, уникальность ID, длины строк, корректность дат, интервалов, ссылок и отсутствие пересечений. Если данные некорректны или версия неизвестна, показать ошибку и заблокировать изменения. Не очищать и не перезаписывать исходное значение автоматически; удаление допустимо только после явного подтверждения сброса по разделу 12.1. Отсутствующая ссылка на библиотеку допустима только после нормализации в `null`, без потери самой задачи.

В одной вкладке состояние хранится в памяти; читать всё хранилище при каждом перерисовывании не нужно. Сохранять после каждого подтверждённого изменения, без отложенного сохранения, которое может потеряться при закрытии страницы.

При событиях `storage` и возвращении фокуса перечитывать значение. Если обнаружено изменение извне, валидировать его и обновлять интерфейс. Если открыта форма с несохранёнными изменениями, заблокировать её сохранение и предложить закрыть и заново открыть на актуальных данных. Перед любой записью сверять `revision` с сохранённой, при несовпадении отменять локальную операцию и загружать новые данные.

Удаление ключа в другой вкладке означает сброс: закрыть устаревшие формы, очистить локальное состояние и показать сообщение об изменении данных. Не восстанавливать прежние задачи автоматической записью из памяти. Отсутствующий ключ допустим как пустое состояние; следующее создание данных начинается с новой ревизии.

Одновременная запись из двух вкладок не имеет гарантии атомарного разрешения конфликтов через один `localStorage`. Для первой версии поддерживается работа в одной редактирующей вкладке. При обнаружении внешних изменений выводится сообщение «планировщик изменён в другой вкладке. продолжайте редактирование в одной вкладке». Не обещать полноценную синхронизацию вкладок при запуске через `file:`.

Ограничение запуска через файл: стандарт не гарантирует одинаковое поведение `localStorage` для `file:` в разных браузерах. Перемещение или переименование файла, смена браузера либо очистка его данных могут привести к отсутствию прежнего хранилища. Это ограничение среды, которое нельзя устранить в рамках трёх файлов без другого способа хранения. В справке указать «открывайте один и тот же файл в одном браузере; очистка данных браузера может удалить задачи». Источник: [документация MDN о localStorage](https://developer.mozilla.org/en-US/docs/Web/API/Window/localStorage).

## 16. Техническая реализация, безопасность и скорость

Использовать HTML5, CSS и обычный JavaScript. CSS подключается относительным путём, JS обычным внешним скриптом с `defer`, без модулей и `fetch`, чтобы не зависеть от ограничений загрузки модулей при `file:`. В HTML установить `lang="ru"`, UTF-8 и метатег viewport. Формат дат в интерфейсе `ДД.ММ.ГГГГ`, часы `ЧЧ:ММ`, локаль `ru-RU`.

Внешние библиотеки, CDN, сетевые шрифты, аналитика, cookies и сетевые запросы отсутствуют. Системный стек шрифтов. Размещение тех же файлов в `.ru` зоне не требует изменения кода; данные такого адреса будут отдельны от хранилища локального файла.

Пользовательские названия и описания выводить через `textContent` и значения полей. Не вставлять их в `innerHTML`, не использовать `eval`, `new Function` и inline-обработчики. Описание является обычным текстом, ссылки в нём автоматически не превращаются в активные элементы.

Drag-and-drop переносит только внутренний тип записи и ID. При обработке проверять наличие ID в текущем состоянии. Внешний текст, HTML и файлы не принимать как задачи. Использовать только известные поля, не сливать произвольные объекты из хранилища в настройки или прототипы.

Логи не должны выводить полное содержимое задач. В интерфейсе ошибки описывают действие и способ исправления, без технических стеков.

Не перестраивать всю страницу при поиске или галочке. Сетку создать один раз на неделю; использовать делегирование событий, фрагменты DOM и обновление затронутых областей. При прокрутке и dragover не читать `localStorage` и не сканировать все задачи. Для проверки пересечений сгруппировать задачи по дате. Текущую дату обновлять одним таймером, а не таймером для каждой карточки.

Целевой объём: до 1000 записей библиотеки и 5000 конкретных задач. Это объём для проверки, а не жёсткий лимит. Нельзя молча удалять старые задачи ради размера. При переполнении хранилища использовать обработку ошибки записи.

Светлая тема в стиле строгого бумажного планировщика. Цвета задать CSS-переменными:

- фон страницы `#F3F4F2`;
- поверхность `#FFFFFF`;
- основной текст `#202622`;
- вторичный текст `#59645C`;
- линии `#D9DED9`;
- основной акцент `#285943`;
- текст основной кнопки `#FFFFFF`;
- ошибка и просрочка `#9F2D2D`.

Для кнопок сбросить системное оформление через `appearance: none`, задать `font: inherit`, а также явные `color`, `background-color` и `border` для обычного состояния и селекторов `:hover`, `:active`, `:focus`, `:focus-visible`, `:disabled`. Цвет надписей дочерних элементов должен наследовать заданный цвет кнопки, без случайного системного тонирования. Сброс не применяется к галочкам выполнения. Остальные интерактивные элементы тоже имеют явно заданные цвета всех состояний. Сброс оформления не должен удалять видимый индикатор фокуса. Не полагаться на цвет браузера по умолчанию и не использовать одну только прозрачность для отключённого состояния. Цвет не должен быть единственным признаком просрочки или выполнения.

Размер основного текста 14 пикселей, текст карточек не менее 12 пикселей. Минимальная ширина колонки дня 150 пикселей; план при нехватке ширины прокручивается горизонтально. Левая колонка остаётся доступна. Проверить экраны 1024×768, 1366×768 и 1920×1080, масштаб браузера 100% и 125%. На 1024 пикселях прокручивается только план, левая колонка остаётся неподвижной; модальные окна не выходят за границы окна. При меньших размерах сохранять работоспособность через прокрутку, отдельный мобильный дизайн не нужен.

Рабочие дни могут не помещаться по высоте и используют прокрутку: диапазон 06:00–23:00 нельзя сжимать до нечитаемого вида ради полного отображения. Области выходных равны половине видимой высоты недельного плана.

Использовать семантические кнопки и подписанные поля. Все операции имеют альтернативу перетаскиванию. Видимый клавиатурный фокус, управление Tab, фокус внутри модального окна и возврат к элементу открытия после закрытия обязательны. Ошибки полей связывать с полями, сообщения о сохранении и удалении объявлять через `aria-live`. Галочка имеет доступное имя с названием задачи и не открывает карточку при нажатии.

## 18. Проверки и критерии приёмки

Разработчик проверяет реализацию фактически в браузере, особенно локальный запуск. Не заявлять проверку браузера или сценария, если она не выполнена. Поддержка рассматривается для актуальных настольных Chrome, Edge, Firefox и Safari с доступным `localStorage`; в отчёте указать конкретные проверенные браузеры и версии.

| проверка | ожидаемый результат |
| --- | --- |
| открытие `index.html` через `file:` без интернета | интерфейс работает, внешних запросов нет, доступность хранения проверена |
| первый запуск | нет автоматически созданных задач, есть кнопка примеров |
| загрузка примеров | три записи библиотеки, четыре экземпляра, один выполненный и один просроченный |
| повторное открытие того же файла | данные восстановлены в проверенном браузере |
| сетка | пять рабочих колонок и одна разделённая колонка выходных, буфер отдельно |
| границы времени | 06:00–06:30 и 22:30–23:00 разрешены, 05:30 и начало 23:00 запрещены |
| шаг времени | 09:15 и длительность 45 минут не принимаются |
| соприкасающиеся интервалы | 09:00–09:30 и 09:30–10:00 разрешены |
| пересечение и вложенный интервал | операции запрещены, исходная задача сохранена |
| скрытая выполненная задача | её интервал занят и обозначен, пересечение не допускается |
| задача без времени в плане | сохранение запрещено; задача без размещения допустима в буфере |
| библиотека на два дня | два ID, независимые галочки и сроки |
| изменение и удаление библиотечной записи | существующие экземпляры не теряют свои поля и не удаляются |
| срок сегодня после окончания рабочего интервала | задача ещё не просрочена |
| переход через локальную полночь | задача со вчерашним сроком попадает в просрочку |
| дата UTC отличается от локальной | день и срок соответствуют локальной дате |
| галочка и её снятие | отметка времени корректна, просрочка обновляется |
| буфер просроченных | та же запись, дубликаты экземпляров не создаются |
| перенос с конфликтом | старое размещение остаётся, новая запись не появляется |
| перенос с автоматическим сроком | дата размещения и срок обновлены на новый день |
| перенос с отдельным сроком | перетаскивание сохраняет срок без диалога, форма требует выбора; режим не меняется скрыто |
| перенос выполненной задачи | запрещён до снятия галочки |
| возврат в буфер | слот освобождён, срок и длительность сохранены |
| дублирование | новый ID в буфере, без срока и галочки |
| удаление | отмена диалога ничего не меняет, подтверждение удаляет запись, ошибка записи сохраняет её |
| сброс данных | требуется точное слово и подтверждение, удалён только ключ планировщика, при ошибке успех не заявлен |
| недельный отчёт просрочки | отбор по дате срока, итоги недели отдельно по дате размещения |
| пустая неделя | нулевые показатели, 0%, понятные пустые состояния |
| ручной HTML в названии и описании | отображается текстом, код не выполняется |
| повреждённый JSON, неверный интервал, неизвестная версия | сообщение, исходное хранилище не перезаписано |
| отказ или переполнение хранилища | нет ложного сохранения, операция отменена |
| внешнее изменение данных | состояние перечитано, устаревшая форма не сохранена |
| три размера экрана и масштаб 125% | кнопки читаемы во всех состояниях, горизонтально прокручивается только план, левая колонка неподвижна |
| компактная карточка 30 минут | галочка и название помещаются, время доступно при наведении, фокусе и открытии, нет перекрытия соседнего слота |
| лимиты ввода | счётчики и maxlength согласованы, превышение объявляется, пустое после обрезки пробелов название не принимается |
| переход из отчёта | открыта нужная неделя, карточка видима горизонтально и вертикально, прокручена именно нужная область дня |
| клавиатура без мыши | создание, планирование, редактирование, галочка, отчёты и удаление доступны |
| 5000 задач и 1000 библиотечных записей | нет зависания при навигации и поиске на проверенном компьютере; результаты замеров указаны |

Для логики пересечений, сроков и переноса выполнить отдельные автоматизированные проверки без включения дополнительных файлов в итоговую поставку. Визуальные и локальные сценарии проверять браузером. Заявлять «самая быстрая версия» без сравнительных замеров нельзя.

## 19. Результат реализации

Поставка содержит только `index.html`, `style.css` и `script.js`, которые работают из одной папки. `concept.md` и `tz.md` являются документацией проекта и не подключаются к странице.

Итоговый ответ разработчика указывает пути к трём файлам, краткую инструкцию открытия, выполненные проверки и фактические ограничения. Никаких действий по публикации или созданию внешних сервисов не требуется.

Продукт принимается, когда перечисленные функции работают, данные сохраняются в проверенной локальной среде, расписание не допускает пересечений, просрочка появляется после окончания дня и перенос не создаёт копии существующей задачи.
